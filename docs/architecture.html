Five surfaces, one agent factory

Vikram is a spec-driven Pydantic AI runtime. Every front end, whether the terminal, an editor, the desktop app, HTTP or Telegram, calls the same build_agent(). That factory reads an agent.toml, resolves a model provider, and attaches tools, MCP servers, skills and hooks.

The trust boundary matters most. Specs with cli_only = true, such as coder with its file-write and shell tools, pass the surface guard only from a local surface. The HTTP, threaded and Telegram paths refuse them.

Request paths

Terminal and editor

Runs in-process with approval prompts on stdio, or as editor permissions over ACP.

cli.py | acp.py → streaming.py → build_agent → agent.run

Desktop app

Tauri starts a loopback-only vikram-api --gui, which needs VIKRAM_GUI_TOKEN. Each session runs in its own worker process.

Studio → api_gui.py → session.py → session_worker.py → build_agent

Stateless chat

POST /chat reuses a cached agent under the conversation id chat:<agent>.

api.py → build_agent → agent.run

Threads and Telegram

Messages are queued as durable DBOS workflows. History is loaded from SQLite before the run and saved after it.

api.py | telegram.py → dbos_gateway.py → gateway.py → build_agent
